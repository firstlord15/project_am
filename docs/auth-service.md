# Документация сервиса аутентификации
**Название модуля:** `auth-service`

**Зона ответственности:** Регистрация и аутентификация пользователей, выдача и валидация JWT-токенов, отзыв токенов при выходе из системы, предоставление информации о текущем пользователе.

### 1. Архитектура и Доменная модель

Сервис изолирован и имеет собственную базу данных (PostgreSQL). Основные бизнес-сущности:

- **User:** Учётная запись пользователя. Хранит логин, хэш пароля, email, телефон, роль, а также признаки активности (`enabled`) и блокировки (`accountLocked`) учётной записи.

Токены не хранятся в базе данных — access- и refresh-токены являются самодостаточными JWT, а их отзыв (revocation) реализован через Redis (см. раздел 3).

### 2. Технологический стек

- **Язык и фреймворк:** Java 17, Spring Boot 4
- **База данных:** PostgreSQL
- **Хранилище отозванных токенов:** Redis
- **Аутентификация:** Spring Security, JWT (HS256, симметричный секретный ключ) через библиотеку `jjwt`
- **Конфигурация окружения:** `.env`-файл через `springboot4-dotenv`

### 3. Зависимости и интеграции

Сервис не делает синхронных HTTP-запросов к другим модулям.

Токены подписываются и проверяются общим секретным ключом (`JWT_SECRET`, HS256) — этот же секрет используется остальными сервисами (например, `finance-service`) для самостоятельной валидации подписи без обращения к `auth-service` по сети.

Отзыв токенов (logout, принудительная блокировка) реализован через Redis: при отзыве токен помечается как недействительный, и при последующей проверке (`/refresh`, а также в `JwtAuthenticationFilter` остальных сервисов) отклоняется, даже если срок его действия ещё не истёк.

### 4. API Эндпоинты

| Метод    | Путь                     | Описание                                             | Доступ        |
|----------|--------------------------|-------------------------------------------------------|---------------|
| **POST** | `/api/v1/auth/register`  | Зарегистрировать нового пользователя, выдать токены   | Публичный     |
| **POST** | `/api/v1/auth/login`     | Аутентифицировать пользователя, выдать токены         | Публичный     |
| **POST** | `/api/v1/auth/refresh`   | Обновить access-токен по refresh-токену               | Публичный     |
| **POST** | `/api/v1/auth/logout`    | Отозвать токены, завершить сессию                     | Авторизован   |

Access-токен возвращается в теле ответа (`accessToken`). Refresh-токен передаётся клиенту только через `HttpOnly`-cookie (`refreshToken`, путь `/api/v1/auth/refresh`) и никогда не попадает в JSON-тело ответа — это защита от кражи токена через XSS.

### 5. Конфигурация и запуск окружения

Для локального запуска сервиса требуются следующие переменные окружения (задаются через `.env` в корне модуля):

* `DB_HOST` — адрес базы данных PostgreSQL
* `DB_PORT` — порт базы данных
* `DB_NAME` — имя базы данных
* `DB_USERNAME` — пользователь БД
* `DB_PASSWORD` — пароль БД
* `REDIS_HOST` — адрес Redis
* `REDIS_PORT` — порт Redis
* `REDIS_PASSWORD` — пароль Redis
* `JWT_SECRET` — общий секретный ключ для подписи и валидации JWT (Base64, минимум 256 бит)

Команда для локального запуска инфраструктуры (PostgreSQL, Redis) через Docker:
`docker-compose up -d`
